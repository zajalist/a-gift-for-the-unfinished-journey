# Auxiliary drone source and import lane

The authored source is `SourceArt/Characters/Drone/drone01.fbx`. Offline audit finds five skinned parts, 5,587 control vertices, about 10,130 triangles, five bones (`root`, `rotor_fl`, `rotor_fr`, `rotor_rl`, `rotor_rr`) and one 2-second `Spin` stack. Four PBR images are embedded as JPEG bytes, despite `.png` paths inside the FBX. The parts carry ×100 model transforms. Editor readback measured the imported visible width at 79.96 cm; do not add another scale conversion.

`python Tools/Drone/import_drone.py audit` and `extract` are offline. `extract` writes the four unchanged embedded images to `Saved/Drone/Textures` with truthful `.jpg` extensions. `python Tools/Drone/make_sfx.py` writes six mono, 48 kHz PCM files to `SourceArt/Audio/Drone`. `python -m unittest discover -s Tools/Drone/tests -v` validates the rig, 2-second clip, audio format, DC, levels, and rotor-loop join.

With the sole editor gate held, no PIE or standalone game, and the editor responsive, run **one command at a time**:

1. `python Tools/Drone/import_drone.py read` to inspect current state.
2. `python Tools/Drone/import_drone.py mesh` to import the skeletal mesh, skeleton and `Spin` animation without rebuilding physics or importing the four embedded textures. A single FBX import might exceed Hayba's five-second limit; if it does, inspect the editor log and use `read` before any retry.
3. `python Tools/Drone/import_drone.py finalize` to rename and save `SK_AuxDrone`, `SKEL_AuxDrone`, `A_AuxDrone_Spin`. Check `read` before moving on. Run `verify` for skeleton association, four rotor children, corresponding Spin tracks, the 2-second animation and roughly 80 cm wide mesh. Interchange may suffix the four rotor bones with `1` because each mesh part has the same name; `verify` accepts that only when all corresponding animation tracks are present. For bounds, `verify` spawns a temporary `SkeletalMeshActor`, assigns the mesh to its registered component, reads `SystemLibrary.get_component_bounds`, and destroys the actor before the size assertion. It does not save that actor to the level. An unregistered component returned zero bounds in this editor. If Interchange produces a different asset set or the registered probe returns an unexpected size, stop and diagnose; do not rename unrelated assets.
4. Run `python Tools/Drone/import_drone.py texture BC`, then `N`, `R`, `M`, separately. They create `T_AuxDrone_*` under `/Game/SaskartaGaea/Characters/Drone/Textures` with color, normal and mask compression.
5. Run `python Tools/Drone/import_drone.py material`. It creates `M_AuxDrone` with BC color, N normal and R/M mask samplers, enables skeletal mesh usage, compiles with zero errors, then assigns it to the skeletal mesh slots. Inspect the mesh in the viewport: check rotor animation, orientation, correct scale, and all four texture roles.
6. Import each audio name separately with `python Tools/Drone/import_drone.py audio NAME`: `SFX_Echo_Ping`, `SFX_Echo_Return`, `SFX_Drone_RotorLoop`, `SFX_Drone_Scrape`, `SFX_Drone_FallImpact`, `SFX_Drone_OpticsSnap`. `RotorLoop` is looped and primed. The ping and return are dry mono sounds; runtime traces determine echo delay and location. Route/mix in the native/controller integration; the current WAV peak does not dictate in-game loudness.
7. The swarm-specific carrier line is `Auxiliary units. Visual relay.` It was rendered with `python Tools/Audio/make_carrier_voice.py --engine sapi --robot light --lines Tools/Drone/voice_lines.json --out Saved/Drone/Voice` and copied unchanged to `SourceArt/Audio/Drone/VO_Carrier_CV_DRONE_02.wav` (2.62 s, 48 kHz mono PCM). `python Tools/Drone/import_drone.py voice` imports it under `/Game/SaskartaGaea/Audio/CarrierVoice/VO_Carrier_CV_DRONE_02`, matching the class/attenuation/virtualization of `VO_Carrier_CV_BOOT_01`. The root story sidecar should use the same line text and ID. No story source was edited here.
8. Run `read` again and inspect saved packages. Drone mesh and SFX imports stay under `/Game/SaskartaGaea/Characters/Drone` or `/Game/SaskartaGaea/Audio/Drone`; the voice uses the existing CarrierVoice folder.

For the approved single sequence, the camera/vehicle fall is at road 3,700 m and the swarm arrives at 3,860 m. The native controller can use `SK_AuxDrone` and `A_AuxDrone_Spin` for several visible swarm members, then keep one drone on the camera rig. Trigger `SFX_Drone_OpticsSnap` at sensor failure, `Scrape` and `FallImpact` at the staged vehicle fall, `Echo_Ping` for each pulse and `Echo_Return` at traced reflectors, with `RotorLoop` on the drone world-audio path. Use the new drone feed as a source on the carrier CRT. Preserve the story reveal: no person or life sign in this sequence.
